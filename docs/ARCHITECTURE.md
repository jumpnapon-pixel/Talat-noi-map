# How the map is built

The published map is a single file, `index.html`, plus `assets/` (photos and artwork) and
`data/` (OpenStreetMap geography and the street network). `index.html` is generated by
`npm run build` from the sources in `src/`.

## Source layout

| Path | What it is |
| --- | --- |
| `src/recovered/01-libraries-and-scene.js` | Runtime and libraries (React 19, three.js, Radix UI, zod, lucide), geography helpers and the 3D scene builder, recovered from the original compiled bundle. The 3D parts are no longer used (see "The removed 3D view") |
| `src/recovered/02-app-components.js` | The map's own components: place schema, navigation and street maps, place card, photo-queue editor, and the unused 3D map and structure editor |
| `src/app/*.js(x)` | Readable app code: app shell, editor UI, storage, undo/redo |
| `src/data/published-seed.json` | The published edition built into the page (shown until the shared database answers, and on hosts without one) |
| `src/styles/app.css` | Recovered Tailwind and app styles |
| `src/styles/editor.css` | Editor styles |
| `src/index.template.html` | Page template |
| `scripts/build.mjs` | Build script |
| `tests/editor.e2e.mjs` | End-to-end tests (Playwright) |

The original project's source code was not available, only its compiled bundle. The bundle
was split into the two `src/recovered` files and formatted. Their identifiers are the
original minified names. The build concatenates the recovered files and the app files inside
**one function scope**, so the app code can use recovered components directly.
`src/app/internals.js` gives each one a readable alias:

| Alias | Recovered name | |
| --- | --- | --- |
| `NavigationMap` | `pE` | the geographic navigation map |
| `VisitorPlaceCard` | `mE` | the visitor's place card |
| `PhotoUploader` | `z3` | photo picker with resize and upload |
| `PlacesSchema` | `W1` | zod schema for places |
| `createPlaceRecord` | `Ng` | a new place with every field filled |

## Positions

Each place has two independent positions (see `src/app/geo.js`):

- **Pin on the illustration**: `x`, `y` as percentages (2–98) of the hand-drawn artwork used
  by the "Illustrated" and "Original" views. **Add pin** and **Move pin** set these: the
  editor taps the illustration and the tap is converted to percentages of the artwork
  (`handleFlatMapClick` in `src/app/App.jsx`). Pins closer than 52 px are spread apart with
  a leader line (`spreadMarkers`).
- **Real location**: `lat`, `lng`, used by the navigation map, street map and walking
  directions. Set with **Set real location** (a tap on the navigation map) or typed in. A new
  place has none (`null`) until an editor sets it, and is left out of navigation until then.

The artwork is stylised and rotated: the existing places' artwork positions are 130–860 m
away from their real location when mapped linearly, and a fitted transform is still 15% off
on average. So neither position is computed from the other. A place created from the
navigation map (fieldwork photo queue) starts at the artwork position of the geographically
nearest place, flagged `illustrationEstimated`.

## Storage, drafts and publishing

`src/app/store.js` chooses a store when the page opens:

| Where the page runs | Store | Editing |
| --- | --- | --- |
| claude.ai artifact | `ArtifactMapStore`: the artifact's shared database (`db`), asset store (`assets`) and viewer permissions (`user`) | Editors and the Owner |
| `localhost` (`npm run serve`) | `LocalMapStore`: this browser's localStorage and IndexedDB | yes, local preview |
| any other host | `StaticMapStore`: the built-in edition, read-only | no |

Database documents (artifact):

| Document | Who reads | Who writes | Contents |
| --- | --- | --- | --- |
| `map/published` | everyone | Editors, Owner | the visitor edition: approved places (plus the old 3D structures list, kept for compatibility) |
| `map/draft` | Editors, Owner | Editors, Owner | the shared draft (all places), `revision`, `publishedRevision` |
| `map/lock` | Editors, Owner | Editors, Owner | short lease used while saving or publishing |

- **Save draft** takes the lease (retrying for a little longer than a lease lasts, since
  leases have no release and a reloaded page gets a new holder), re-reads the draft and only writes if its `revision` is
  still the one the editor started from. Otherwise it reports a conflict and keeps the
  editor's changes. The editor can then download them, load the newer draft, or replace it.
- **Publish** copies the approved places of the *saved* draft to `map/published` and
  records `publishedRevision`.
- Photos are uploaded to the artifact's asset store. Places keep the durable `/_blob/<id>`
  path. Photos that ship with the map (`assets/…`) are linked directly.
- Unsaved edits are copied to `localStorage` (`talat-noi-editor-recovery:*`) and offered
  back the next time the editor opens.
- When the database is empty, visitors see the built-in edition and the editor starts its
  draft from it.

## Changes to the recovered code

Each change is marked with a "Talat Noi editor" comment.

- Place schema: accepts relative `assets/…` photos (the existing data uses them), asset-store
  (`/_blob/…`) and local-preview photos; adds `photoCaption` and `illustrationEstimated`.
- Photo upload goes through the active store instead of `POST /api/photos`.
- 3D scene builder: pins can be rebuilt on their own (`setPlaces`); `pinHeight` exposed.
- 3D map: placement sessions (move and add), drag with camera lock, tap-to-place, snapping,
  nudge, top-down view, overlapping-pin chooser, imperative `apiRef`, tap detection that
  uses event timestamps.
- Place card: shows the photo caption.
- Photo queue: the "Place on 3D map" button now reads "Place on illustration".
- Visitor place card and navigation panel: wording that referred to the 3D map now refers to
  the map (English and Thai).

The original app shell (minified `yE`) and its `fetch` shim for `/api/*` were replaced by
`src/app/App.jsx` and `src/app/store.js`.

## The removed 3D view

The map used to open on an interactive "Illustrated 3D" view (three.js), where editors also
dragged pins and arranged the illustrated landmark models ("3D structures"). That view was
removed: the map now opens on the "Illustrated" view, and pins are placed on the
illustration.

- The app no longer renders `fE` (the 3D map) or the structure editor, and the
  `placement-bar.jsx` controls (nudge arrows, top-down view, Confirm position) are gone.
- The recovered 3D code and three.js are still in `src/recovered/`, unused. Removing them
  would make the page smaller.
- Saved drafts and published editions still carry a `structures` list. It is validated and
  saved unchanged so older data keeps loading, but nothing shows it.

## Sharing the map as one file

`npm run build:standalone` writes `dist/talat-noi-map.html`: the visitor map with every image
and data file it uses embedded (about 15 MB). It opens straight from disk or any web host,
makes no network requests and is read-only (no editor, since it has no shared database). It
shows the edition built into the page (`src/data/published-seed.json`), so places published
later from the claude.ai map are only included after that file is updated.

## Visitor guide (research brief of 11 Nov 2026)

- Place fields added to the schema (with defaults, so older records still load and saving
  keeps them): `previewEn/Th`, `kind` (`place`, `field-note`, `area-guide`), `aliases`,
  `related` (place ids), `sources` (`{id, title, url}`), `entranceConfirmed`,
  `entranceConfirmedOn`, `entranceNote`, `researchReviewedOn`, `editorNotes`. Saving writes
  the zod-parsed places, which drop unknown keys, so new fields must be added to the schema.
- `src/app/place-card.jsx`: the visitor card (`GuidePlaceCard`) and **Plan your walk**
  (`WalkGuide`). `src/app/guide.jsx`: labels, bilingual interface copy, search text, the
  walk chapters (`WALK`) and a small paragraph and *italic* renderer (no HTML).
- Directions gate: `tnCanRoute(place)` in `src/recovered/01-libraries-and-scene.js` (alias
  `canRoute`) is true only when `entranceConfirmed` is on, the place is not an area guide and
  it has coordinates. `Gd` (Directions links, the menu's destination list) and `HN` (walking
  steps) both check it, so no map control can route to an unconfirmed place.
- Search matches `nameEn`, `nameTh`, category and `aliases`.
- The 15 entries were written from the brief by a script that matched each record by its
  current title and photo file before updating it in place; the Thai "story and visit
  note" block was split into `storyTh` and `tipTh` where the visit advice begins.

## Soft launch: hours, phone layout and sharing (brief of 11 Nov 2026)

- Hours fields (schema, with defaults): `hoursStatus` (`published`, `listed`, `check`,
  `unknown`, `outdoor`, `area`), `hoursScope`, `weeklyHours` (`mon`…`sun`: "", "closed" or
  ranges), `hoursExceptions` (`{date, hours, noteEn, noteTh}`), `hoursLabelEn/Th`,
  `hoursNoteEn/Th`, `hoursReports` (other listings), `otherTimes` (Mass, office),
  `hoursSources`, `hoursReviewedOn`, `hoursEditorNotes`. `scripts/guide/apply_hours.py` holds
  the researched values and their sources (H01–H31).
- `scheduleState(place, now)` in `src/app/guide.jsx` reads Bangkok time with
  `Intl.DateTimeFormat(..., {timeZone: "Asia/Bangkok"})`, so a phone in another time zone
  gets the same answer. Only published/listed schedules reviewed in the last 183 days can be
  open or closed; overnight ranges spill into the next morning; an empty day is "not listed",
  not "closed"; a special date replaces that day.
- Phone layout (`src/styles/guide.css`, visitor view only; also short landscape screens):
  title/language row, full-width search and a filter button (categories, an optional
  “Open by schedule now”, map views), a visible reset when filters are on, a floating
  Map/List and Plan your walk dock, zoom above it, and pin labels only for the selected pin
  until the visitor zooms in.
- Plan your walk passes its chapter to the card, which then offers **Next stop** and nearby
  alternatives from the same chapter.
- Small photos use 240 px thumbnails in `assets/thumbs/` (falling back to the full photo).
  The illustration shows a loading message, and if it fails, a message with **Open the
  list**.
- `src/app/share.jsx`: Share map. `SHARE_URL` is the only link used by the share sheet, copy
  link and QR. The QR is drawn by the vendored `qrcode-generator` (MIT,
  `src/vendor/qrcode-generator.js`); **Download QR** saves a 1,215 px PNG through the
  artifact `downloads` capability or a normal download.
